# Changelog

## [Unreleased]
These changes ship in 0.2.0 when it is tagged (the version in `pyproject.toml` is already 0.2.0).
### Added
- `SourceStore` (`lilavati.core.provenance`) and `ProvenanceGate(store)`: citations are resolved against the sources a pipeline read (SEC company facts, PDF or HTML pages, Ind AS disclosures), checking hash, tag, period, filing date, page snippet and value. Without a store the gate checks only the form, as before. Registration helpers `PDF10KParser.register_in` and `india_filings.register_disclosure`; `record_hash` is the one canonical hash for XBRL fact records. Tutorial 08 Step 3b.
- MCP tool `get_filing_figures` (`lilavati-mcp-corporate-filings`): one 10-K or 10-Q's own line items, missing items, identity checks and ratios. `sec_filing.fetch_filing_extraction` runs the flow live; `EdgarClient.fetch_submissions`, `EdgarClient.get_json`, and `resolve_cik(..., online=True)`, which looks up any listed ticker in SEC's company list.
- `lilavati.connectors.sec_filing`: filing-anchored XBRL extraction (submissions index → the filing's own facts by accession, end date and duration), missing items, identity checks, statement text window and deterministic ratios. `scripts/validate_sec_filings.py` (5-company pilot: 71 of 71 values found in the filing documents) and `scripts/run_filing_comparison.py` (LLM alone vs LLM + Līlāvatī vs Līlāvatī alone; results in `results/filings/`).
- Tutorial 08: a real 10-K, three ways.
### Fixed
- `EdgarClient.extract_line_item` returned prior-year comparatives for a fiscal year (Apple FY2026 revenue 391,035, the FY2024 figure, instead of 478,834); it now takes the filing's own period.
- 10-K PDF parser, checked against Apple's FY2026 10-K statements: the tax line matched "Income before provision for income taxes" (159,237 instead of 27,062); total debt dropped non-current term debt (11,903 instead of 80,111); common equity was read from the par value in a wrapped label (0.00001 instead of 104,815). Labels now match at the start of a line first, rows take their trailing amounts across wrapped lines, section headers are skipped, repeated rows are summed, and `ExtractedFiling10K.missing_items` lists items not found instead of passing 0.0 as reported. Validation page `docs/validation/connectors.md`.
- `EdgarClient` sent a made-up contact (`admin@lilavati.ai`) in its User-Agent; SEC requires a real one. It now reads `LILAVATI_SEC_USER_AGENT` (or the `user_agent` argument) when a request is made.
- `EdgarClient.extract_three_statement_model` preferred contract revenue over total revenues (Walmart: 706,413 instead of 713,163); it now uses the same order as `sec_filing`.
- `EdgarClient.extract_three_statement_model` (MCP `get_company_filing_statements`) filled fields it did not find and called the result verified: on Apple's FY2026 10-K, retained earnings 132,175 (net income; reported 13,700), common equity −20,082 (104,815), inventory 0 (14,541), total debt 68,208 (80,111); operating income set to net income when untagged (J&J); opening cash back-solved from the cash flows, so `cash_reconciled` was always `True`; Walmart refused because it tags no total liabilities. It now uses the fiscal year's 10-K only (`sec_filing.filing_for_fiscal_year`), records each derived field's formula (`derived`), lists unreported optional fields (`not_reported`), raises naming any missing required item, checks opening cash + cash flows + exchange-rate effect = closing cash, and runs balance checks on reported totals only (`checks`). The MCP tool returns `{"error": ...}` instead of raising. `scripts/validate_sec_filings.py` now also checks the model: 86 of 86 reported values found in the Apple, Microsoft and Walmart 10-Ks; J&J and JPMorgan refused.
- 10-K PDF parser: `cash_reconciled` was `True` for both years whatever the numbers; a missing equity line became assets minus liabilities (the balance check then held by construction), a missing common equity line became total equity, and missing investing or financing totals became minus capex or minus buybacks and dividends. Checks now use the cash flow statement's own beginning and ending balances and the parsed totals; an item not found is listed and not substituted, and a check with a missing input is not run (flag `False`). `ExtractedFiling10K.checks` lists them.
- Ind AS crosswalk (`IndiaFilingsClient.parse_ind_as_disclosure`): cost of goods sold took only the first Schedule III cost line (4,000 instead of 4,800 on the test disclosure), operating income left out other expenses (4,300 instead of 1,800), tax took current tax alone; keys not given became 0.0 and were cited; `cash_reconciled` was set to `True` after back-solving opening cash. It now returns `IndASParseResult` (`derived`, `not_reported`, `checks`), raises on missing required items, checks the Ind AS 7 cash reconciliation, and cites only items given. The test disclosure is a fictional company (it was Infosys with made-up figures).
- `FinancialSearchAgent.search_entity` returned Apple's FY2024 figures, with made-up page numbers (48, 50, 52) and the hash of an empty string, for any symbol whenever SEC could not be reached, and a fixed Indian revenue (890,000) for any company. It now takes the latest 10-K filed on or before the as-of date (point in time) through the filing-anchored path, cites each fact, and returns no facts with a note when data is unavailable (`SearchReport.notes`). Ind AS search says it is not implemented.
- `FinancialResearchAgent` reported a fixed target price (245.0), "sound" earnings quality and "Paris-aligned" carbon intensity for any symbol, from hard-coded inputs, and fell back to Apple's revenue and assets. The dossier now has `data_source` and `assumed_inputs`, no target price, a labelled illustrative baseline when no filing data is retrieved, and a thesis that says it is a workflow demonstration.
- XBRL citations used a placeholder page (1) and a hash of an identifier string. `CitationRef.page` is now optional (`None` for XBRL facts) and `doc_hash` is the SHA-256 of the fact record SEC serves (`sec_filing.fact_hash`), which can be re-fetched and checked. `EdgarClient.extract_line_item` no longer fills a missing filing date, period or accession with defaults.
- Golden case LILAVATI-T1-001 cited "Item 8, pp. 48-52" of Apple's FY2024 10-K; its cash-flow figures are constructed for the exercise (operating cash flow 118,264 against the filed 118,254). The citation now says so; the question, and so its content hash, is unchanged.
- The framework paper said the `ProvenanceGate` resolves citations against a document hash store; it checks only that a citation is well formed.
- Pilot total quoted as "64 of 64" in the changelog, roadmap, Tutorial 08 and release notes; the pilot table and results file give 71 of 71.

## [0.2.0] - release candidate (not yet tagged; see docs/releases/v0.2.0.md)
### Fixed
- Beneish M-score used wrong coefficients (TATA 4.037 → 4.679; LVGI +0.0327 → −0.327, per Beneish 1999). Scores quoted in docs refreshed.
- Almgren-Chriss schedule: clipping bug made very risk-averse schedules hold all shares to the end; volatility now in price units; discrete-time solution with η̃ = η − γτ/2; adds expected cost and variance (removes a stray 0.5 factor in variance).
- Merton solver could return non-solutions (equation errors up to 90%) for distressed / long-horizon inputs; now a bracketed 1-D solve with a residual check. Invalid inputs raise `ValueError`.
- Derivatives: SABR near-ATM skew term dropped (now matches QuantLib to ~1e-12); `calibrate_sabr` failed for index-level forwards; `is_arbitrage_free` was only an RMSE test (now checks butterfly and call-spread arbitrage of fitted prices); butterfly check depended on strike order; CRR tree silently mispriced when the up-probability left [0, 1]; non-finite / degenerate inputs now raise `ValueError`.
- Covenant check reported a false breach for ratios exactly at the limit (float rounding); non-finite inputs to invariant checks now raise a clear error.
- SLB covenant could report a missed target when met exactly (float rounding); WACI rejects zero-sum / negative weights; `total_carbon_footprint` relabelled (not PCAF financed emissions).
- Econometrics: GARCH p/q were passed to `arch` swapped (GARCH(1,2) returned α₂ = 0); OU half-life used the ln2/(1−φ) shortcut (27% high at φ = e^−0.5), now −ln2/ln φ; unconverged GARCH fits raise instead of returning start values; collinear/constant/non-finite inputs and invalid significance levels raise. Example/tutorial half-lives refreshed (2.74 → 2.38 days).
- Financial ML: fractional-d search returned a placeholder d*=1.0, p=1.0 when nothing qualified (now raises); ignored the caller's target p-value at d=0; float grid could exceed 1.0; d* rounded below step precision; exact barrier touches missed through float rounding; invalid inputs (NaN, zero/negative prices or horizon) now raise.
- LLM client: Gemini and Anthropic paths accepted `tools` but never sent them or parsed tool calls, so agents never used tools on those providers. Now implemented (Gemini functionDeclarations / functionCall / functionResponse incl. thoughtSignature echo and schema sanitising; Anthropic tool_use / tool_result with role merging). Bounded retries with backoff on 429/5xx/timeouts (`ModelSpec.max_retries`).
- Agent runtime: `max_reflection_iterations` also capped tool rounds, so multi-step tool plans ended with an empty answer while reporting success; now a separate `max_tool_rounds` and an `AgentOutput.completed` flag. Tool errors are flagged to the model (`is_error`).
- `run_llm_baseline.py --resume` re-ran unparsable answers as well as provider errors, re-rolling model failures and inflating scores; it now re-runs only errors and empty replies. Each record now stores the model's `finish_reason`, and summaries count `truncated` replies separately.
- `run_llm_baseline.py` scored answers unparsable when a model's inline `<think>` reasoning contained braces (2 `qwen3.6-27b` answers); reasoning blocks are now stripped first. New `--rescore` re-scores stored replies without API calls.
- Benchmark: generated case ids collided across set sizes (`generate_cases(2026, 2)` and `(2026, 4)` both had `GEN-T2-000`, different bonds); ids now carry seed and size (`GEN-S2026-N4-T2-000`), cases have a content hash (`case_content_hash`), and old ids resolve via `legacy_case_id`. Generated content is unchanged.
- Benchmark prompt: the `bond_price` key said "price of the 5-year bond" for generated bonds of 2-10 years (gpt-oss-120b priced a 10-year bond as 5-year); prompt v3 fixes it and every record stores `prompt_version`.
- Ollama preset pointed at the server root instead of its OpenAI-compatible `/v1` endpoint.
- `case_content_hash` included expected answer values, whose last digits depend on the platform's math library, so hashes differed between macOS and Linux CI; it now hashes only the question (scheme v2), and stored hashes were recomputed by `scripts/migrate_case_hashes.py` without changing any other field.
- `paired_difference` ordered pairs by content hash, so the seeded bootstrap CI changed when the hash scheme did; pairs are now ordered by case id (published Qwen3.8 bounds moved from +0.1083/+0.6875 to +0.1125/+0.6917; bootstrap Monte Carlo error is about ±0.01).
